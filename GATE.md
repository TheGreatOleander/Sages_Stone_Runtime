# Sage’s Stone Runtime — GATE

This document defines the gate.
The gate is the enforcement authority of the runtime.

The gate does not explain.
The gate does not persuade.
The gate decides.

---

## 1. Definition of the Gate

The gate is the sole authority that determines whether an action,
capability, execution, or extension is permitted to exist within the runtime.

Nothing enters the runtime without passing through the gate.
Nothing operates inside the runtime without remaining compliant with the gate.

---

## 2. Scope of Authority

The gate governs:

- Execution entry
- Capability introduction
- Runtime modification
- Tooling attachment
- Observation mechanisms
- Scoring pathways
- Result finalization

There are no exceptions based on intent, urgency, or success.

---

## 3. What the Gate Checks

Before approval, the gate verifies:

- Compliance with LAW
- Compliance with all runtime invariants
- Absence of privileged paths
- Absence of collapse interference
- Absence of observer influence
- Deterministic alignment with declared constraints

Failure of any check results in rejection.

---

## 4. Gate Invocation

The gate is invoked:

- Before execution begins
- Before any new capability is introduced
- Before any runtime-facing change is accepted
- Before any tooling is allowed to attach
- Before results are finalized for acceptance

The gate is not a one-time check.
It is continuously authoritative.

---

## 5. Rejection Semantics

When the gate rejects an action:

- The action does not occur
- Execution does not proceed
- No partial state is preserved
- No fallback path is allowed

Rejection is final for that attempt.

---

## 6. Non-Override Clause

The gate cannot be overridden by:

- Administrators
- Maintainers
- Contributors
- Tooling
- Configuration
- Success metrics

If something requires bypassing the gate, it is unlawful by definition.

---

## 7. Silence Is Not Permission

If the gate cannot determine legality:

- The action is rejected

Ambiguity is treated as violation.
Permission must be explicit.

---

## 8. Gate and Observers

Observers may exist only if they pass the gate.

Any observer that:
- alters execution
- affects timing
- injects state
- biases scoring

is rejected or reclassified as a system and judged accordingly.

---

## 9. Failure of the Gate

If the gate itself is found to be unenforceable, incomplete, or bypassable:

- Execution must halt
- Results are invalid
- Further operation is forbidden until resolved

A broken gate invalidates the runtime.

---

## Final Authority

The gate enforces LAW.
The gate enforces invariants.
The gate enforces collapse.

The gate does not care why you want something.
The gate only decides whether it is allowed.
